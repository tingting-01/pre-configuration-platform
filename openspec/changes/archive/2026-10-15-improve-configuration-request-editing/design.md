## Context

参见 [proposal.md](proposal.md)。`ConfigurationComplete.tsx` 是普通新建、工单编辑、复制新建、从模板新建、新建模板和模板编辑共用的表单；工单编辑通过 `/configuration?edit=<id>` 进入。表单目前将 WisDM 配置放在 `configData.system`，模板转换另有字段映射，详情页与导出逻辑各自处理系统配置。

列表已有 Edit：创建者或管理员可编辑，`Done`/`Released` 时禁用。详情页没有 Edit。后端更新接口校验创建者或管理员，但尚未按已发布状态拒绝配置更新。列表使用横向滚动表格，Actions 是最后一列。

## Goals / Non-Goals

**Goals:**

- 新字段在现有配置、模板和导出链路中往返不丢失，旧数据无需迁移。
- 列表和详情使用一致的编辑入口规则。
- 在共用表单中复用一个取消确认交互，并按当前表单模式返回合适页面。

**Non-Goals:**

- 不改变工作流状态名称、状态流转及现有角色体系。
- 不增加全站离开提醒；本次确认仅由新增 Cancel 触发。
- 不改变复制新建的保存语义或模板使用次数规则。

## Decisions

### 1. 在 `system` 中保存独立布尔字段

表单增加 `wisdmWhitelist: false` 初值，在 WisDM 主开关启用时、Provisioning 上方显示独立复选框。回填使用 `config.system.wisdmWhitelist ?? false`，新建、更新和模板保存的两处系统配置构造均写入该字段；模板字段路径映射和默认表单值同步补齐。关闭 WisDM 主开关仅隐藏子控件，沿用当前表单对其他 WisDM 子值的保留方式，不隐式改写 Whitelist。

详情页显示启用状态；配置导出沿用“过滤默认值”规则，将 `false` 作为默认值，确保 `true` 被导出。对比方案是建立新的顶层字段或存储表；现有 `configData.system` 已承载同类设置，新增结构只会增加转换成本。

### 2. 详情页直接沿用列表的编辑资格

详情页在导出按钮前展示 Edit，并直接复用列表现有判断：当前用户是创建者或管理员，且工单状态按大小写归一后不是 `done`/`released`。两处保留相同的局部表达式，不为两处简单判断新增工具模块。点击后进入现有 `/configuration?edit=<id>` 路由，编辑表单继续使用既有接口和权限行为。

### 3. 在原表格内固定 Actions 列

保留现有横向滚动容器和表格，给 Actions 表头、各行对应单元格设置相同的固定右侧定位与列宽，使用不透明背景和合适层级防止滚动内容透出；核对悬停行背景、按钮点击、窄屏和表头对齐。对比方案是拆出第二张操作表格，容易产生行高与滚动同步问题。

### 4. 共用表单的 Cancel 使用来源与模式确定返回目标

在保存按钮旁放置 `type="button"` 的 Cancel，点击后显示确认框；关闭或选择继续编辑时保留当前状态，确认放弃时不触发提交。确认放弃后保持确认层直至页面卸载，避免路由切换完成前短暂露出已放弃的编辑表单。

编辑工单通过历史返回回到实际入口，既支持从详情进入，也兼容从列表直接进入；工单详情的返回按钮明确进入 `/dashboard`，保证“详情 → 编辑 → 取消 → 详情 → 返回”最终直接到工单列表，不再次显示已取消的编辑页。普通新建、复制新建、从模板新建返回 `/dashboard`；模板编辑返回 `/templates`。从 Templates 页新建模板时不具备模板 ID，因此入口通过路由 state 携带 `/templates` 返回目标，取消时按该来源返回模板列表；缺少来源信息的普通新建仍按工单新建处理。保存中禁用取消，避免请求已经发出时出现“放弃”却仍完成保存的歧义。

对比方案是所有场景统一使用历史返回；直接访问、刷新或新标签打开表单时，历史上一页可能不是预期业务页面。另一方案是新增 URL 模式参数，但仅模板列表入口需要补充来源，路由 state 足以表达且不改变现有地址。

## Risks / Trade-offs

- [旧工单或旧模板缺少新字段] → 读取时默认 `false`，不批量改写历史记录。
- [导出过滤器遗漏 `true`] → 同步覆盖详情页和通用导出逻辑，验证启用值在导出结果中存在。
- [固定列遮挡内容或行操作] → 设置一致列宽、背景和层级，并在窄屏横向滚动下验证。
- [取消时已有保存请求在途] → 保存期间禁用 Cancel；确认放弃只处理尚未提交的表单状态。
- [共用表单无法仅凭模板 ID 识别新建模板入口] → Templates 新建入口携带返回目标，表单按来源返回模板列表；普通新建保持原有 Dashboard 回退。
- [取消后历史记录重新显示编辑页] → 编辑取消使用历史返回，详情返回使用明确列表地址，并在导航完成前保留确认层遮罩。

## Migration Plan

无需数据迁移、新增依赖或后端接口修改。旧记录在读取时按默认值显示；回滚前端后，新字段仍可保留在 `configData.system`，不影响旧版本读取。
