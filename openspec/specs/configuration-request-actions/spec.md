# Configuration Request Actions Specification

## Purpose

统一工单列表与详情页的编辑资格，让横向滚动时仍能操作列表，并让用户从共用配置表单离开前明确确认，减少入口不一致和误丢未保存内容。

## Requirements

### Requirement: 工单详情与列表使用一致的编辑资格
系统 SHALL 在工单详情提供 Edit 操作，其可用性与工单列表一致：创建者或管理员可编辑尚未发布的工单，状态为 `Done` 或 `Released` 的工单不可编辑。

#### Scenario: 有权编辑未发布工单
- **WHEN** 创建者或管理员打开状态未发布的工单详情并点击 Edit
- **THEN** 系统进入该工单的配置编辑表单并回填现有内容

#### Scenario: 无权编辑工单
- **WHEN** 非创建者且非管理员打开可访问的工单详情
- **THEN** Edit 不可用，与列表中的编辑权限一致

#### Scenario: 已发布工单
- **WHEN** 用户查看状态为 `Done` 或 `Released` 的工单
- **THEN** 列表和详情的 Edit 均不可用

### Requirement: 横向滚动时 Actions 列可用
系统 SHALL 在工单列表横向滚动时将 Actions 列固定在表格右侧，保持表头和对应行操作的对齐与可点击性。

#### Scenario: 滚动宽表格
- **WHEN** 列表宽度超过可视区域且用户横向滚动
- **THEN** Actions 表头及各行操作保持在右侧可见，且不遮挡同列按钮

### Requirement: 配置表单提供带确认的取消操作
系统 SHALL 在共用配置表单的普通新建、工单编辑、复制新建、从模板新建、新建模板及模板编辑场景提供 Cancel。点击 Cancel SHALL 显示放弃未保存内容的确认框，不得直接保存或提交表单。

#### Scenario: 继续编辑
- **WHEN** 用户点击 Cancel 后选择继续编辑或关闭确认框
- **THEN** 确认框关闭，用户留在表单，当前输入保持不变

#### Scenario: 取消工单编辑
- **WHEN** 用户在编辑已有工单时确认放弃修改
- **THEN** 系统不提交本次表单修改，并返回编辑前的工单详情页或工单列表

#### Scenario: 从详情取消编辑后返回列表
- **WHEN** 用户从工单详情进入编辑、确认取消并回到详情后，再使用详情页返回操作
- **THEN** 系统直接进入工单列表，不再次显示已取消的编辑页

#### Scenario: 取消新建工单
- **WHEN** 用户在普通新建、复制新建或从模板新建时确认放弃
- **THEN** 系统不创建工单，并返回工单列表

#### Scenario: 取消模板编辑
- **WHEN** 用户在模板编辑场景确认放弃
- **THEN** 系统不更新模板，并返回模板列表

#### Scenario: 取消新建模板
- **WHEN** 用户从模板列表进入新建模板并确认放弃
- **THEN** 系统不创建模板，并返回模板列表

#### Scenario: 确认放弃期间保持遮罩
- **WHEN** 用户在确认框中确认放弃并等待目标页面显示
- **THEN** 系统保持确认层覆盖当前表单直至离开，不短暂露出已放弃的编辑页面
